# Sub2API v0.2.15 二改版更新说明

更新日期：2026 年 10 月 9 日。

本次合并上游 v0.2.15 更新，保留尚未被上游覆盖的本地二改功能。与上游重叠的请求 TPS 展示已统一使用上游实现。

## 保留的二改功能

- 上游中转站额度查询：继续支持 New-API 和 Sub2API 协议，保留账号创建、编辑、余额展示及查询接口；异常响应不会被误报为零余额。
- Gemini 授权修复：保留开户后补取项目 ID，以及手动重新授权时填写项目 ID 的能力。

## 本次更新

- 合并上游新增的 Cline 和 Command Code 平台，以及由平台清单驱动的账号表单与协议能力配置。
- 请求速率统一使用上游“输出 TPS”：输出 Token 除以包含首字等待的总耗时，单位为 `tok/s`，与上游运维统计口径保持一致。
- 合并上游协议转换、模型发现、计费、WebSocket、账号管理及前端请求竞态等修复。
- Go 工具链升级到 1.27.2，并同步上游依赖更新。

## 重叠功能清理

- 删除本地“生成 TPS”的额外显示、`formatThroughput` 计算函数、两项专属测试及中英文翻译。
- 用量表组件、对应测试和中英文用量翻译文件恢复为上游 v0.2.15 实现，避免展示两套 TPS。
- 上游中转站额度查询、Gemini 项目 ID 补取与重新授权修复继续保留；它们尚未被上游对应实现覆盖。
- 本次清理更新源码及 GitHub 仓库。此前部署的镜像未重新构建；上线时需按下方要求串行限内存构建。
- 清理后的用量表、输出 TPS 计算、账号余额单元格及国际化检查共 125 项测试通过；四个 TPS 相关文件已确认与上游 v0.2.15 完全一致。

## 小内存服务器构建注意事项

更新和重新编译时，前端类型检查、前端打包、Go 测试、Go 编译及镜像构建必须串行执行。Go 使用 `GOMAXPROCS=1` 和 `-p 1`，测试限制工作进程数量，并为构建进程设置总内存硬上限。

本次在约 3.6 GiB 内存的服务器上，以 1550 MiB 构建内存硬上限、禁用构建进程 swap、每 5 秒检查可用内存的方式完成构建。前端类型检查与打包分开执行；Go 的 `ent` 和 `internal/service` 包关闭编译内联，以降低编译内存需求。这些是本次本地构建参数，通用 Dockerfile 未默认启用这些参数。

数据库和部署配置已在本地备份，原镜像保留用于回退。服务器的数据库备份、账号凭证、环境文件及本机部署覆盖配置不纳入本次代码提交。
